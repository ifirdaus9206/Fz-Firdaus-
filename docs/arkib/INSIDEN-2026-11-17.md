## 1. Telegram: "masuk mesej baru padahal topik sembang belum habis"

### Punca sebenar (dua lapis)

**(a) Sesi pecah setiap mesej — punca utama.**
Setiap mesej masuk dari Telegram membawa `message_thread_id` + `is_topic_message=True`
walaupun chat itu DM biasa. Adapter Telegram menjadikan nilai itu sebahagian daripada
kunci sesi (`gateway/session.py`, cabang DM: `dm_parts.append(source.thread_id)`),
jadi **satu mesej = satu sesi baharu**, konteks sembang hilang.

Bukti: `~/.hermes20/sessions/sessions.json` — 48 kunci bersufiks thread untuk DM bos:

| Masa | Kunci sesi | Thread |
|---|---|---|
| 18:18 | …:26050 | 20261117_181824_8ed62105 |
| 18:58 | …:26054 | 20261117_185812_0d49e2ef |
| 19:39 | …:26075 | 20261117_193932_11c91d23 |
| 19:57 | …:26084 | 20261117_195730_b188786b |

**(b) Gateway mati dibunuh Android, kemudian "auto-resume" menghantar turn baharu.**
`logs/gateway.log` 19:44:40: `Previous gateway life … exited UNCLEANLY (no exit path ran —
SIGKILL / OOM)`. Punca: wake-lock **tidak dipegang**. `hermes-console/tools/keeper.sh`
melepaskan wake-lock setiap 5 minit apabila semua sihat → telefon tidur → Android bunuh
Termux. Selepas mati, gateway `Scheduled auto-resume for 1 restart-interrupted session(s)`
→ satu mesej baharu muncul di tengah sembang.

### Pembetulan

1. `tools/hermes-source/{plugins,hermes-agent/plugins}/platforms/telegram/adapter.py`:
   DM hanya dihormati sebagai "topic" jika chat itu memang dalam `extra.dm_topics`.
   Selain itu DM = **satu sesi berterusan**.
   Ujian sebenar (`venv/bin/python`, mesej palsu DM thread=26084):
   ```
   DM biasa        -> thread_id = None | chat_type = dm
   DM topic config -> thread_id = 26084
   Forum group     -> thread_id = 26084
   SEMUA UJIAN LULUS
   ```
2. `hermes-console/tools/keeper.sh`: wake-lock **tidak lagi dilepaskan** selagi
   `~/.hermes20/wake_lock.enabled` wujud. Diambil semula sendiri jika hilang.
   Status selepas pembetulan: `HELD (wake-lock aktif — phone tak tidur)` · `auto-mode: ON`.
3. Tampalan adapter perlu gateway dimuat semula — dijadualkan sekali sahaja
   (cron `b5af60c245a1`, 20:10) melalui `POST /api/svc/hermes-gateway {action:restart}`.
   Log: `~/.hermes20/logs/gw_restart_once.log`.

Mematikan semula: `bash ~/hermes-console/tools/wake_ctl.sh off`.
